# Design collection guidance

This fork is a curated design-document collection, not an application framework. Read [README](README.md) and [contribution guidance](CONTRIBUTING.md) before editing. Preserve upstream license notices and attribution; extracted visual tokens do not establish ownership of a brand identity.

Each collection entry lives under `design-md/<site>/`. Inspect that entry's README and actual files instead of assuming the root README's advertised `DESIGN.md` and preview layout is present everywhere. Keep categories, names and links consistent with the entry. Preserve the distinction between a website-inspired reference and an official design specification.

For an entry change, verify its typography, color values, spacing, components and responsive claims against supplied or inspected evidence. Label uncertain observations. Do not invent tokens, proprietary font access or accessibility guarantees. Keep previews and their source description aligned when previews exist, and check relative links resolve in the repository.

No package manifest, build script or CI test gate was found in this tree. Verification is content review and changed-link/path inspection; a visual preview requires an actual render before claiming fidelity. Report which pages or files were inspected and which visual checks remain unperformed.

Upstream contribution guidance asks for an issue before a PR. Preserve that convention for upstream submissions, while confirming the intended destination for MTG-only changes. Avoid adding global agent policy or runtime-specific skills to this content repository.
